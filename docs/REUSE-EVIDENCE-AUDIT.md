# 知识复用失败审计与更正 · 2026-09-08

原先把知识卡对照的“正确率三组均为 0”解释成摘要质量不足，证据不成立。逐项核对冻结回答、送审输入和最终评分后，发现盲审引用运输有确定性缺陷。54 个旧语义评分已停用；原始答案、gold、资格记录和失败记录均保留。这个审计不是一次新模型评分。

## 已定位的缺陷

1. `rubric._neutral_evidence` 将证据重编号为 E1、E2……，但只替换答案中的 A/B/C 标签，没有替换原本就使用 E/M 标签的知识复用答案。例如原回答的 E2（深度守卫）、E4（解析入口）、E6（复现代码）、E8（观测输出）被重排成 E1、E2、E3、E4，答案仍使用旧编号。52/54 个试次有这一错误；另外两个答案没有显式标签。
2. `knowledge_reuse_eval._references` 为原始试次保存的引用只有路径、范围和哈希。旧盲审没有从冻结材料中补回引用正文。52 个带引用的答案因此缺少原引用的正文；金标补充材料不能替代正确绑定的候选引用。
3. 已生成的知识卡包含生产阶段的 T 标签，但回答阶段只登记 M1/E 标签。3 个结构化卡片答案沿用 T 标签而被运行时校验判为无效。新呈现层将生产轮次引用映射为可见材料 M1，原模型产物不改写。

历史评分中，有 14 个答案的必要要点全部被判满足，最终仍因引用关系被判错。这些计数用于证明评分输入需要修复，不意味着可以把这 14 个答案直接改判正确。

## 具体复现与修复

- 稀疏编号 `[E2][E6][E8]`、材料 `[M1]`、普通 `[A1]` 现在统一通过一次性映射改写；不连续替换，避免编号连锁变化。
- 未知引用保留未知身份，新的证据编号避开它，防止伪造引用被意外改成合法引用；重复且歧义的原标签直接拒绝。
- 从本次冻结报告中的正文及附件恢复引用，校验材料哈希、文件哈希和范围，不读取当前工作树充当旧版来源。
- 新盲审包独立生成输入哈希；旧 run hash 和原始答案保持不变。54/54 个答案的映射与引用正文检查通过，完整的新评分请求估算输入最大 6,999 token，没有调用模型重评。
- 统一验收通过绑定历史报告 SHA-256/run hash 的审计通知显示 `invalid_review`，停止输出旧语义差值。通知缺失或被篡改不能重新启用旧评分。

另外执行了独立 C 验证：使用同一个固定输入 harness，A 按默认宏编译 cJSON.c，B 仅将该翻译单元的 `CJSON_NESTING_LIMIT` 改为 1001。A 的深度 1001 返回 `NULL / parse_end=1000`，B 返回 `ok / parse_end=2003`，与部分旧答案的核心预测相符。这不替代完整要点和引用复核。

## 仍然真实存在的问题

卡片确实没有压缩原本很短的会话。按 Unicode 字符数（不是 token）计算，cJSON 原文 536、卡片 588；lwIP 原文 600、卡片 987。标题、边界描述和重复来源占用空间。字符膨胀是可以直接确认的现象，不能由此推断语义质量变差。

部分回答还存在真实的执行性或论证问题：例如 A/B 命令使用未定义的 `$SRC`，或把“调高上限后仍失败”直接当成否定深度限制，未排除编译参数未生效和新分配失败。修复引用不自动解决这些问题，也不保证重评分有正向收益。

Wiki 路径另有协议执行问题。432 个正式试次中，115 个最终输出为证据包，95 个记录 `model_plan_invalid:JSONDecodeError`。按 cJSON 的源码/自由 Wiki/渐进 Wiki 三组分别为 20/6/14 次降级；lwIP 为 34/25/16 次。这是现有 Agent 整体表现的一部分，但使“单独归因于 Wiki 内容质量”不成立。历史记录只留下异常类型，不能据此断言是模型多输出说明、服务响应封装或截断导致；需要开发材料上的协议样本才能确认根因。

## 为什么之前的验证没发现

已有盲审测试主要覆盖 A1 转 E1；经验评测夹具验证请求次数和表面标签合法性，没有检查原始 E 标签在重排前后仍指向同一正文。假评分器又直接返回预置分数，无法发现真实引用错配。测试通过证明覆盖到的约束成立，不证明缺失的约束成立。此次新增跨命名空间、稀疏编号、未知标签、冻结正文和原回答不变的回归。

## 重现审计

完整原始账本在本地忽略目录。以下命令只读取账本，不调用模型，不写回原答案：

```sh
python -m codeatlas.eval.review_packet_audit \
  --campaign data/proof/campaign-v10 \
  --batch 0bfa4a7453e3534cae5d12b5be22798bf885aec97813f94bca76b14e1015e3e6 \
  --report docs/runs/curated/PROOF-KNOWLEDGE-REUSE-V4.json \
  --out docs/REUSE-EVIDENCE-AUDIT.json
```

逐试次原始/修正包哈希、受影响数量和正文长度见 [结构化审计](REUSE-EVIDENCE-AUDIT.json)。旧语义评分不能通过删除引用门禁或手动补分恢复；修正包需要新的、可追溯的评审记录。未决 Wiki 判断属于另一问题，不能混为“只剩一项”的收尾说明。
