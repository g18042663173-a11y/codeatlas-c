## 二、剩余工作

### P0 — 投递前必须做（1 天）

**① 配真实 API key 跑通 LLM 路径**

这是当前最大的风险点。13 项 mock 测试兜底了异常处理，但**从未打过真实 API**。

```bash
export LLM_API_KEY=sk-xxx
export LLM_BASE_URL=https://api.deepseek.com/v1
export LLM_MODEL=deepseek-chat

codeatlas summary --db data/lwip.db --use-llm    # 只对 fan_in≥3 的节点调用
codeatlas wiki --db data/lwip.db
```

**验收标准**：对比规则版和 LLM 版的 `one_liner`。
现在规则版产出的是函数名分词（`netif_add` → "netif add"），基本没有信息量。

- 如果 LLM 版明显更好 → 保留"LLM 增强摘要"的表述，README 里放一组前后对比
- 如果差别不大 → **老实把"LLM-Wiki"改称"分层文档生成"**，不要在简历里用前一个词

预计成本：lwIP 上 fan_in≥3 的函数约 150 个，DeepSeek 几毛钱。

**② README 加截图（2~3 张）**

招聘者不会 clone 你的仓库，只会扫一眼 README。建议：
- `codeatlas impact` 的终端输出（最有说服力，一眼看懂价值）
- 消融表（证明有数据）
- Web 界面（证明是完整系统）

### P1 — 有时间就做（各 1~2 天）

| 任务 | 验收标准 | 收益 |
|---|---|---|
| 换真实嵌入模型 `bge-small-zh-v1.5` 重跑消融 | EVAL.md 里 embedder 字段是真实模型名 | 去掉"用 TF-IDF 冒充语义检索"的软肋 |
| candidate 细分 unresolved | mbedtls 上 369 条能分成宏展开/声明缺失/解析错误三类 | 补上当前最弱的一环 |
| 评测集扩到 120 题 + 负例标注 | 每类 ≥20 题 | 置信区间收窄 |

### P2 — 加分项

- 生成质量评测（LLM-as-judge 或人工打分）
- 宏变更的跨 TU 精确失效追踪
- 同名符号消歧专项评测 —— 证明符号通道在什么条件下才有价值
  （目前它测出的是负增益，能拿数据说明"什么时候有用"会比现在更完整）

### 明确不做

多用户 / 权限 / 审计 / 项目隔离。超出个人项目范围，README 里写在"后续演进"即可。

## 五、简历文案

### 一行版（技能/项目栏）

> CodeAtlas：面向大型 C 工程的 AI 知识库，Clang AST 代码图谱 + 混合检索 + 人机协同审核

### 三行版（推荐）

> **CodeAtlas — 大型 C 工程 AI 辅助开发知识库**｜Python / libclang / SQLite(FTS5) / FastAPI
>
> 基于 Clang AST 构建代码知识图谱（lwIP 协议栈 13.5 万行，6.4K 节点 / 11.7K 关系），严格区分编译器确认关系与词法推断关系，后者不参与调用链与变更影响分析；实现依赖闭包指纹的增量解析，无变更时复用全部 124 个翻译单元，并以引用计数保证增量结果与全量重建逐边一致。
>
> 设计定长「检索摘要头」压缩调用上下文至 ≤200 token，使图多跳扩展在固定预算下装入节点数从 5 提升至 18；融合符号精确、BM25、向量与图关系并以 RRF 排序，引入 A/B/C/D 证据分级与拒答机制。自建 59 题评测集（金标取自 AST 事实）并做分题型消融以排除循环论证，图多跳扩展使结构性查询（调用者/影响面/2 跳影响）召回提升 11~31 个百分点，并如实报告其在语义查询上增益为零。

### 写的时候注意

- ✅ 写"大型 C 工程"，**不要写"基带代码仓库"** —— 你验证用的是 lwIP / mbedtls / cJSON。
  基带可以作为**设计动机**提一句："参考通信协议栈这类回调密集的代码特征"，这是真话。
- ✅ 所有数字必须能在 `bash demo.sh` 里复现出来。写了就要能当场跑给人看。
- ✅ 主动写局限。README 末尾那一节别删，面试时主动提比被问出来强。
- ✅ **不要写"整体召回提升 X 个点"**。要写"结构性查询召回提升 11~31 点，
  语义查询增益为零"。前者会被追问到崩，后者显示你做过分题型拆解。
