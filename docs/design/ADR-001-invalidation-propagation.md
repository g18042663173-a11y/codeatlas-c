# ADR-001：依赖失效与停止条件

状态：已实施保守版本，精细依赖优化保留为后续。来源：[手册未定义·本次新增]。

实现边界：知识卡记录全部已解析实体和配置，Wiki 记录文件事实及子页摘要。传播工作列表已接入快照构建并保存审计事件；超过阈值选择全量重验证。目前新快照本就全量解析，不声称最小重建。相同规范化输入可以复用；未完备的函数级消费分析不用于放行。未启用预处理分支、switch fallthrough 和别名语义没有被证明，只保存显式范围及 candidate/unknown 边界。

每份知识保存真正消费的实体、源码、宏和配置指纹。A/B/C 是来源等级；certain/candidate 是关系置信度；fresh/stale/needs_revalidation 是可用状态，三者不混用。

定义、签名、规范化 token（保留常量/操作符）、结构骨架、宏与构建依赖分别哈希。签名和骨架相等不能证明语义等价。缺少依赖或抽取不完整时保守失效，不自动恢复人工卡。

变更首先影响直接消费方，再检查调用/引用和上层摘要依赖。确定性工作列表使用 visited 防环；默认风险深度 2，超过深度仍未消除风险，或受影响实体超过 30%/500 个，执行全量确定性重验证。不能在截断边界把未知知识默认为有效。

父页只消费结构化摘要；消费输入未变可复用正文。commit 和行号属于引用元数据，不独立导致重新生成语义正文。宏、预处理配置和返回常量变化必须重新验证。

测试包括：纯位置变化；返回 0→1；宏/-D/公共类型变化；调用环；超阈值；旧卡主锚点不变但依赖变化。审计事件保留触发实体、规则、路径、前后指纹、时间与快照。
