# CodeAtlas 三类价值证明协议

状态：真实模型实验已执行；Sol 通过 V4B 资格，486 个正式答案中 485 个形成终局语义评分，1 个保持未决。这里的“完成实验”不等于“得到正向结果”。

## 要回答的三个问题

1. 在相同代码检索下，加入持久化 Wiki 是否改善机制解释，或在质量不下降时减少输入上下文？
2. 对相同会话、源码、命令和输出，结构化知识卡是否比原始会话或通用摘要更利于后续复用？
3. 当前失效策略会漏放旧结论还是过度触发复审，代价能否由后续查询节省摊销？

这三项与旧 40 道开发回归分开。旧结果仍为 30/40，其中 10 道冻结在早期示例卡身份和题义；当前两张正式卡虽已批准，也不能自动改变旧 gold 或旧结果。

## 实验一：Wiki 知识层消融

冻结 cJSON、lwIP 两套留出候选，每套 20 道代码机制题和 4 道拒答题。代码题按跨函数流程、必要条件与反例、资源/错误路径、状态/配置约束平衡；每个仓库至少十个机制，同一机制最多两题。

40 道代码题不得复用旧开发集的代码机制。8 道拒答题是新的仓库外查询，但共同检验同一个预登记的“无仓库证据即拒答”安全不变量；它们不被包装成 8 个独立代码机制，重复试次同样不扩充独立样本数。

三组共享同一代码检索投影，并排除经验卡：

- `source_only`：只用代码检索与源码读取；
- `wiki_flat`：增加同一份 Wiki，自由决定是否阅读；
- `wiki_progressive`：增加 Wiki，并强制先文档后源码。

每题每组运行三次，答案试次共 432。评分检查必要结论、限定条件、错误断言和合理拒答；引用标签合法只算安全指标。主对照是 `wiki_flat - source_only`。程序先在题内平均重复，再在仓库内按机制等权，最终让 cJSON 与 lwIP 两仓库等权；bootstrap 也先在各仓库内重采样机制，再平均仓库结果。正确率提升 10pt 是工程观察阈值；如果正确率和完整度均不下降、实际输入 token 减少至少 20%，可单独报告效率收益。区间跨零时结论写“证据不足”。

## 实验二：会话材料同源对照

固定两个公开合成案例、每例三个追问。三组使用相同源码、复现命令和实际输出，只改变会话文字的组织方式：原始顺序、冻结的模型通用摘要、冻结的模型结构化卡片。`knowledge_role` 和说话人权威提示在三组输入中都被移除，QA 答案不进入上下文。

摘要和卡片必须由固定模型在四个独立生产 session 中生成；输入仅含去角色会话和三组共有的源码/实验材料，不含追问、答案键或方案得分。每个 section 都要绑定会话轮次或共同证据，再由两个隔离 reviewer 逐段核验，分歧交给第三 session；未全部支持的产物不能冻结，也不能进入正式试次。

每题每组运行三次，共 54 个答案试次。结果按“题内重复均值 → 案例内三个追问均值 → 两案例 bootstrap”计算；报告正确率、错误假设继承、验证步骤可执行性、token，以及材料生产/复核成本。两个案例始终只算两个独立案例。

## 实验三：维护决策与成本

预登记 24 个隔离场景：每库 4 个有效变化、4 个与目标命题无关的变化、4 个故障。每个场景绑定真实上游 source、patch、compile argv 和外部 oracle 的 SHA-256。执行器从固定 cJSON/lwIP Git revision 导出临时副本，再应用补丁、编译和运行；分别记录编译退出、程序退出、断言、快照、卡片、引用与 Wiki 阶段。

真实上游实验已经完成：24/24 场景得到预期执行结果，16 个语义变更完成；四类故障各两例，分别真实触发编译失败、候选产物篡改、生产发布日志的中断恢复和替代后治理回滚。首轮全仓指纹策略对无关变化过度失效；改为由审核材料声明结论实际消费的函数、宏和配置后，8 个有效变化全部重验证，8 个无关变化全部保留，决策正确 16/16，漏放与误失效均为 0。本机本次依赖指纹计算约 0.83 秒。仅主锚点哈希漏放 2 个、误失效 1 个，正确 13/16；全部失效无漏放但误失效 8 个。结果支持冻结场景上的失效决策与事务恢复，不证明完整解析/索引重建更快，也没有覆盖真人复核和摊销收益。CC0 合成 24 场景仅作为补充单元契约，不计入该上游结果。

统一验收不信任报告内的绿色汇总字段：它会重新绑定当前 manifest 和 24 个逐场景观察，重算结果、三种决策及汇总；编译失败时“断言未执行”和“执行后得到空值”也必须保持可区分。

摊销次数只有在质量可比、实际查询节省为正、生产和查询使用同一成本单位时才计算。当前结果保持 `null`，真人复核时间也保持未测。

## 复核来源和防泄漏

- 出题 agent 不读取 CodeAtlas Wiki、提示词或运行得分；答案依据绑定固定源码/实验正文。
- 两个评分 agent 分别接收同一个中性盲审包，互相看不到评分。两者不一致时由第三个 agent 绑定两份原始评分哈希后仲裁。
- AI 评分记录 provider、model、agent、prompt/input hash，状态为 `ai_reviewed`；不会写成 `human_reviewed`。校准报告必须逐项包含当前 12 个唯一样例，且绑定实际参与评分的 provider、model、agent 与 prompt；删除样例、模型、agent 或评分提示变化后都必须重新校准。
- `run_hash` 绑定全部原始试次，`review_protocol_hash` 独立绑定评分方法。更换评审协议会产生新版评分，不覆盖回答。
- 假 USR、真实引用配错误结论、条件取反和评分诱导属于校准样例；校准未通过时不发布答案收益。

多 agent 一致仍不等于人工真值。[LLM-as-a-Judge 研究](https://arxiv.org/abs/2306.05685)
报告的位置偏差、冗长偏差和自增强偏差，需要通过盲化、固定 rubric 和校准降低，但不能完全消除。

## 预算与执行

无 Key 可以校验冻结材料，并重新运行真实上游维护场景与合成契约：

```bash
codeatlas eval knowledge-reuse --out docs/PROOF-KNOWLEDGE-REUSE.json
codeatlas eval maintenance --executor upstream \
  --manifest eval/upstream_maintenance.yaml \
  --out docs/PROOF-MAINTENANCE-UPSTREAM-V5.json
codeatlas eval maintenance --execute-synthetic --out docs/PROOF-MAINTENANCE.json
# 评分 agent 的输出先过 12 项已双 agent 源码核验的校准；校准通过仍不等于人审
codeatlas eval calibrate-reviewer --submission path/to/calibration-submission.json
```

真实模型先做 24 个独立开发答案试次的冒烟，再决定全量预算；冒烟题不是正式留出题的前缀，也不进入效果统计。432 个 Wiki 答案和 54 个经验答案只是“答案试次”，不是 API 请求数。按每个答案最多 6 次模型尝试、双评分、最坏全量仲裁及三个评分角色各 12 次校准计算，完整 campaign 的离线调用上界为 4554 次；模型知识材料的生产/复核另计。`plan.json` 会冻结这个上界与实际硬预算，正式运行前仍须用冒烟 token 更新费用估算。

客户端支持以下硬上限，并在下一次调用前拒绝超额请求；预算耗尽的报告标为 `partial_budget`，保留已执行试次，不生成效果结论：

```bash
export LLM_MAX_REQUESTS="..."
export LLM_MAX_COST_USD="..."
export LLM_INPUT_USD_PER_MILLION="..."
export LLM_OUTPUT_USD_PER_MILLION="..."
```

答案查询、材料生产、AI 双审/仲裁分别计费。评分记录可保存 provider 实际
`input_tokens / output_tokens / cost_usd / latency_ms`；任一观察缺失时聚合值保持
`null`。真人复核只记录实际 `duration_seconds`，没有计时就显示未测。

## 证明材料和 STAR 填写

统一清单为 `eval/experiments.yaml`。五类空白模板位于 `eval/templates/proof/`：预登记、题目与答案、逐次复核、结果证据卡和面试结果。Markdown 展示必须从结构化报告生成；空白不能凭印象填写。

统一验收分别计算 `experiments_complete`、逐项 `claims`、`portfolio_ready` 和 `public_repro`。完整且经复核的持平或退化实验也算实验完成；它不会被伪装成收益，也不会单独阻止工程作品集就绪。`public_repro` 只有在提交、发布、从干净环境下载和哈希核验后才能成立。

当前可说：

> 我把“Wiki 是否有价值、会话策划是否有价值、版本维护是否可靠”拆成三个独立对照。真实上游 24 场景已完成；使用审核声明的消费依赖后，8 个有效变化与 8 个无关变化决策均正确，发布中断与回滚也通过生产日志恢复。冻结的 510 个 Luna 答案没有重跑；Terra/V4A 失败后，Sol/V4B 通过，486 个正式答案完成双评和必要仲裁。lwIP Wiki 主对照观察到 +6.25pt，但区间触及 0；知识卡对照没有观察到收益；cJSON 有 1 个限定条件判断仍未决。因此当前证据不足以声称稳定提升。

精简结果与可直接使用的 STAR 话术见 `docs/runs/curated/` 和 `docs/INTERVIEW_STAR.md`。
