# 如何判断 CodeAtlas 的知识层有没有价值

更新：2026-09-05。本文定义实验，不是效果报告。真实模型尚未运行，独立语义金标尚未完成用户审核。

## 要回答的问题

我们要验证：在固定源码和相同模型预算下，持久化的工程知识是否让 Agent 更准确地解释机制、少漏必要条件，或者在答案质量不下降的前提下减少读取成本。

找到一个金标函数，只能证明召回；读过 Wiki，只能证明使用了工具；单个漂亮案例，不能证明整体提升。

## 两种对照不混用

### 整套系统对比：`eval model --abc`

A 是源码检索与读取，B 在 A 上增加固定分析方法，C 使用 CodeAtlas。三组都是迭代 Agent，使用同一模型、temperature、6 次工具尝试、300 行源码读取上限、8,000 估算输入 token 与 1,200 输出 token 预算。

它回答“整套系统与源码 Agent 相比怎样”，不能把所有差异归因于 Wiki。A/B 当前没有与 C 知识卡相同的会话信息；经验题只能展示知识可用性的差异，不能证明策划质量更好。代码题的质量和 token 单独比较，经验题、拒答题不得混入代码收益。

### 知识层消融：`eval reading`

三组共用同一份代码/结构摘要、符号、certain 图、FTS 词频与 local-hash 向量。预先在隔离副本中排除全部 B 卡和 Wiki 检索块，重新建立相同的代码向量投影。三组代码检索结果的输入哈希相同。

- `source_only`：无 Wiki；读相同的代码证据。
- `wiki_flat`：可以用工具读 Wiki，自行决定顺序。为兼容保留旧参数名，实际含义是“自由阅读”，不是把全部 Wiki 塞进 prompt。
- `wiki_progressive`：同样可以读 Wiki，概念题遵守先文档、再源码的阶段约束。

Wiki 只通过 outline/section 工具提供，不额外混入检索正文。缺少当前 Wiki 时不调用模型做无意义对照，而是返回 `wiki_unavailable`。无 Key 返回 `model_not_configured`。规则结果不能替代模型结果。

主假设是 **Wiki 自由阅读 vs 无 Wiki**：只改变知识可用性，阅读都不强制顺序。次要对照同时报告 **渐进 vs 自由阅读** 与 **渐进 vs 无 Wiki**。不要求渐进策略必须胜过自由阅读，才承认 Wiki 本身有价值；也不能把 Wiki 的收益当成渐进策略的收益。

这项消融控制了代码检索输入，但仍比较完整的“知识可用性 + 阅读策略”。目前并未实现额外的“全文平铺”实验，也不宣称消除了模型预训练时接触公开 cJSON/lwIP 的可能性。

## 题集和答案怎么准备

原有 cJSON/lwIP 各 20 题已经用于发现问题和调整检索，继续作为开发回归集，文件与 gold 不改。即使做到 40/40，也不把它称为独立测试集。

另行准备并冻结语义留出集。当前单仓库效果门禁要求至少 20 道代码题，题量是预先设定的工程下限，不是统计充分性的保证。新增题应覆盖跨函数机制、条件例外、失败路径、版本迁移，补充合理拒答；不能只把现有题换个说法。题目按机制分组，避免同一机制的改写题同时进入开发集和留出集。建议由未参与调参的人出题并检查源码；发现留出失败后可以修复，但该批题随即转为开发数据，后续泛化声明需要新留出集。

每道语义题需要：期望结论、必须说明的条件、禁止的错误结论、固定源码/实验引用、可核验步骤。答案要点独立放在 `--answer-key` YAML 中，绑定原题集 SHA-256；只给评审者，不传入 Agent。

`eval/answer_key.example.yaml` 是未审核格式样例，不能直接跑成正式题集。工具能校验文件和声明，不能自动证明审核人真实存在、题目未用于调参，也不会代替用户签署审核。

例如，cJSON_Delete 的评审不能只检查“提到了 child”或命中函数位置。需要区分：reference 标志与 child 非空共同控制递归；valuestring 的释放另有条件；string 的释放看 StringIsConst；跳过 child 并不意味着不释放节点自身。把真实源码标签贴在“引用节点完全不释放内存”上，仍应判错。

## 试次和评分

1. 固定 seed 的成对交错调度：每题每次重复，随机化三组执行先后。每试次独立 SQLite 副本，不共享上次运行轨迹。
2. 默认每题每组 3 次。异常也保留为试次，仅记录异常类型，不保存可能含鉴权信息的异常原文。不能删掉失败重跑后只保留成功。
3. 盲审包隐藏方案名，打乱展示顺序，提供回答、证据和固定要点。引用格式仍可能暴露方案特征，因此是标签盲审，不是保证评审者无法猜测方案。
4. 每点标 `met/missing/wrong`，另查是否存在重大错误陈述。`correct` 要求要点齐全；`incomplete` 表示遗漏而非实质错误；`incorrect` 包括真实引用配错误结论；`reasonable_refusal` 必须对应拒答 gold。审核者填写身份、日期和依据。
5. 未审核准确率/完整度为 null，展示“待审”，不是 0%。标签合法率、锚点召回、答案正确性分别报告。修改回答或引用后，旧盲审 ID 不再适用。整批审核失败不部分生效。
6. 正确性和安全统计全部原始试次；先按题汇总重复，再对题做 paired bootstrap 描述性 95% 区间。3 次重复不等于 3 道独立题。机制相近的题仍可能相关，不能把区间当作大样本推广证明。

服务端每次完整 usage 才计入 token 对照；超时或缺字段记“未测”，不当作 0。无模型调用的本地拒答确实为 0 次调用。记录延迟 p50/p95、工具次数、累计输入/输出和总 token；不假设输入必然计费相同，也不虚构成本。

## 什么结果才适合 STAR 的 R

比较同一批代码题：ABC 对两个基线分别计算准确率、人工答案完整度差值与上下文 token 差值，不选择对自己更有利的两个不同基线拼接指标。知识层消融的效果门禁仅针对预声明主对照（自由 Wiki vs 无 Wiki）；两项渐进阅读对照完整列出，不事后挑一个更好看的对照作为主结果。

预声明工程阈值：准确率提升至少 10pt；或准确率不下降、答案完整度提升至少 10pt；或准确率与完整度均不下降、代码题输入 token 至少减少 20%。该阈值不等于统计显著性，应同时给出逐题失败与区间。源码锚点提升不再能独立解锁效果门禁。

正式效果声明还要求：固定语义留出金标、完整 3 次对照、逐试次盲审、最终安全门禁、原生规划率等全部满足。40 道开发回归集和 8 题冒烟不能通过这一声明门禁。系统级 ABC 的经验复用指标另列，不能遮盖非经验题退化。

可填写的结果句式（不是已测数字）：

> 在固定版本的 cJSON/lwIP 留出任务上，我保持模型和代码检索不变，对比无 Wiki、自由阅读、渐进阅读。主对照经逐项盲审，加入 Wiki 后的机制解释正确率从 __/__ 提升到 __/__，遗漏条件率从 __ 降到 __；代码题累计输入 token 为 __，相对减少 __。渐进策略的额外影响为 __。仍失败的机制包括 __，因此收益仅限于这批任务，不声称优于通用 Coding Agent。

当前可以说：实现了可重建、有版本和审核边界的知识生产/使用机制；尚不能说已经证明知识层比直接读代码好。

## 还需要的两种证据

- 经验策划增益：在独立隔离实验中，让基线也看到相同的公开原始会话，处理组看到已审核卡；评测新问题而非原问题重放。原始会话绝不进入正式索引。这一同信息量实验尚未实现，不用当前 ABC 经验题冒充。
- 维护代价：在固定变异集上同时测过期漏放和无关改动误失效，保留返回常量、宏/编译参数、类型变化与纯移动/无关变化；记录构建时间、人工复审时间及查询次数，再算摊销成本。当前审核声明的消费依赖已在 16 个冻结语义场景达到零漏放和零误失效，但完整构建、人工复审与摊销收益仍未测，不能只凭决策正确率宣传维护效率。

## 使用

```bash
# 开发回归；需用户在本机配置模型。无 Key 的 reading 只生成 not_run。
codeatlas eval reading --db data/kb.db --tasks eval/tasks_cjson.yaml \
  --runs 3 --seed 17 --out docs/MODEL-READING-CJSON.json

# 独立题集与金标由人冻结后，再加 --answer-key path/to/reviewed-answers.yaml。
# 同样支持 codeatlas eval model --abc --answer-key ... --seed 17。
# *.review.json 为无方案标签的评审包；人工补充逐点评分，另存评分文件。
codeatlas eval review docs/MODEL-READING-CJSON.json \
  path/to/human-reviews.json docs/MODEL-READING-CJSON-reviewed.json
```

输出 JSON、Markdown 和独立评审包；同名结果存在时必须换新运行名，不能覆盖早先失败。评审后另存报告，原始试次保留。协议、调度、答案金标和模型由 evaluation hash 绑定，源码/实现/题集/Wiki/知识卡由 identity 绑定。没有模型结果或没有内容确认时，发布条件仍不满足。
